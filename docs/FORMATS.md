# Формати обміну Studio v1

## JSON

Повний приклад: `examples/demo.als.json`. Кореневий об’єкт:

| Поле | Тип / значення |
| --- | --- |
| schemaVersion | число `1` |
| game | `wildlands` або `breakpoint` |
| sourceLanguage / targetLanguage | непорожні рядки, типово `en` / `uk` |
| entries | масив об’єктів із рядковими полями `id`, `source`, `translation`, `context`, `status` |
| glossary | масив об’єктів із рядковими полями `source`, `target`, `note` |

Усі вказані поля обов’язкові. ID непорожній та унікальний (регістр значущий). `status`: `todo`, `translated` або `reviewed`; два останні вимагають непорожнього перекладу. Порожній оригінал допускається. Глосарій вимагає непорожніх терміна та відповідника; ключ терміна порівнюється без регістру та крайніх пробілів. Додаткові невідомі поля не зберігаються при повторному експорті; не використовуйте цю схему для сторонніх JSON без перетворення.

JSON читається в UTF-8. Невідома версія, неправильні типи та порушення інваріантів відхиляються. Імпорт спершу розбирає та перевіряє всі дані, потім замінює документ; помилка не залишає частково імпортованих рядків.

## CSV

Точний порядок заголовка:

```csv
id,source,translation,context,status
```

UTF-8, кома як роздільник. Експорт: CRLF, усі значення в лапках; лапка всередині поля подвоюється. Імпорт приймає LF/CRLF/CR, UTF-8 BOM, багаторядкові поля та відсутність останнього переносу. Після закритої лапки допускається лише роздільник, кінець рядка або файла. Зайві/відсутні колонки, пошкоджені лапки й некоректний UTF-8 відхиляються. Глосарій та метадані до CSV не входять.

## Синтетичний плагін

Файл `examples/demo.anvilsample` = ASCII-префікс `ANVIL_STUDIO_SAMPLE` + LF + JSON Studio v1. Це **власний формат для тестування інтерфейсу**, не файл Ubisoft і не підтвердження будь-якого формату Anvil.
