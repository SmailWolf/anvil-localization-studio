# Архітектура MVP 0.3

`anvil_core` не залежить від Widgets: модель документа, JSON/CSV, валідація та сховище. UI спершу перевіряє новий документ і лише потім замінює поточний. Збереження атомарне; помилка копіювання попереднього файла зупиняє перезапис.

`anvil_breakpoint` — окрема read-only бібліотека: обмежений індекс v27, контрольоване читання контейнерів, перевірка adler32 із seed 0, рамка ресурсу та Re-Pair-читач текстів. Окремий експериментальний writer і `anvil-build-breakpoint-test` створюють вузький тест двох написів поза грою. Його перевірки та невизначеності описані в [TEST-PATCH.md](TEST-PATCH.md).

`anvil-extract-breakpoint` читає лише два відомі архіви, збирає англійські пакети та обирає патч за однаковим package ID. Стиснені блоки передаються власному процесу helper. На Windows він запускається безпосередньо, на Linux — через Wine. DLL користувача копіюється до тимчасової папки та не поширюється з програмою. Вихід — новий JSON-проєкт; шляхи всередину гри відхиляються до запису. Helper має перевірки довжин і результату декомпресії; перевірки структури та контрольних сум виконує батьківський процес.

## Плагіни

Контракт `include/anvil/formatplugin.h`, IID `org.anvil-localization-studio.FormatPlugin/1.0`:

- `formatId()` — стабільна назва конкретного формату;
- `displayName()` — точна назва та межі підтримки;
- `recognizes(prefix)` — попередня перевірка сигнатури;
- `decode(bytes)` — повний розбір або пояснювальний виняток.

У контракті немає шляху до гри, запису чи встановлення. `plugins/breakpoint` працює з декодованим ресурсом; він не приймає довільні `.forge`. Його перевіряє реальний QPluginLoader. `plugins/sample` — синтетичний тестовий формат.

GUI зв’язаний із перевіреною бібліотекою Breakpoint напряму. Він навмисно не сканує каталог довільних нативних модулів. Qt-плагін — виконуваний код, не пісочниця; майбутній завантажувач потребуватиме явного вибору перевірених модулів. ABI вимагає сумісних компілятора, архітектури, runtime та Qt; несумісна зміна контракту потребує нового IID.

## Ідентифікатори та продуктивність

Проміжна модель зберігає ID `grb:packageID:stringID` та вихідне походження в контексті. Редактор не зливає рядки лише за однаковим текстом і не перенумеровує їх. Модель/формат JSON v1 лишилися сумісними з попереднім MVP.

Під час завантаження великої таблиці proxy тимчасово від’єднується, сповіщення групуються, потім відновлюються колонки. Перевірено відкриття всіх 76 732 записів. Документ залишається в пам’яті; повні архіви гри в пам’ять не завантажуються.

## Подальший розвиток

Наступні окремі кроки: QA плейсхолдерів і глосарія, undo/redo, інкрементальне оновлення проєкту зі збереженням перекладів, розширення перевірених форматів Wildlands. Загальний експорт модів, шрифти й встановлення перекладу не реалізовані. Експериментальний writer проходить зворотне читання, але прийняття патча рушієм ще не перевірене.

## Модуль Wildlands (0.3)

`anvil_wildlands` повторно використовує точний спільний індекс v27/1050 та граматику перевірених непорожніх пакетів, але має власний CFD v1/LZO-декодер, обробку порожнього EManual та профіль/ID `wildlands`/`grw:`. Перевірки Breakpoint не послаблені. `anvil-extract-wildlands` не відкриває жодного ігрового файла для запису; вихід створює винятково поза грою й без перезапису. GUI запускає його окремим процесом і відкриває готовий JSON після успіху. Спільна сигнатура payload не дає автоматичного визначення гри, тому два плагіни вибираються явно. Докладно — [WILDLANDS.md](WILDLANDS.md).

## Локальна модель та оновлення проєктів (0.4)

Окремий `anvil_translation` використовує Qt Network і робочий QThread, не блокує UI під час генерації. `TranslationDialog` тримає результати окремо від документа до явного прийняття, main window застосовує лише вибрані ID з поточного модального сеансу. Подробиці — [LOCAL-MODEL.md](LOCAL-MODEL.md).

`mergeUpdated` у core зіставляє ID та повний оригінал у межах тієї самої гри/мови. Зберігає переклад і статус лише для точного збігу; нові/змінені рядки отримують todo, вилучені не переносяться в новий набір. Глосарій та цільова мова переносяться. GUI зберігає повний знімок старого документа поряд із новим до застосування результату. Це не перевірка сумісності нових версій ігрового формату.

## Пакування (0.6)

`anvil_packaging` — окремий C++ модуль з read-only доступом до оригіналів і виключно новими output-папками поза грою. `anvil-pack-translation` надає pack/assemble; GUI створює знімок поточного документа, запускає його окремим процесом та показує прогрес. Сумісність JSON збережена, жоден метод перекладу не викликає пакування автоматично. Формат, SHA-bound delta, структурна перевірка, обмеження UMAC/шрифту — [PACKAGING.md](PACKAGING.md).
